# RLExpGame - Система анализа телеметрии робота с AI-интерпретацией

## 📋 Описание проекта

**RLExpGame** — это интеллектуальная система для анализа телеметрических данных робота в реальном времени. Проект объединяет машинное обучение, обработку изображений и языковые модели для обнаружения аномалий в поведении робота и генерации креативных описаний ошибок в виде шуток.

### Основные возможности

- 🔍 **Анализ телеметрии**: Обработка данных одометрии, лидара и камеры
- 🤖 **ML-классификация**: Обнаружение аномального поведения с помощью TCN и классификатора
- 🖼️ **Обработка изображений**: Генерация описаний сцен с помощью BLIP
- 💬 **AI-интерпретация**: Генерация креативных шуток об ошибках робота через LLM (Ollama/Qwen3)
- 📊 **Поведенческие индикаторы**: Вычисление 16 различных метрик движения робота
- 🌐 **REST API**: FastAPI-сервер для приема данных и возврата анализа

## 🔄 Процесс работы системы

### 1. Прием данных (FastAPI Endpoint)

**Эндпоинт**: `POST /generate`

Принимает JSON с телеметрией робота:
```json
{
  "batch_id": 1,
  "start_timestamp": 1234567890,
  "end_timestamp": 1234567900,
  "duration_ms": 10000,
  "odometries": [
    {
      "frame_id": "odom",
      "timestamp": 1234567890,
      "position": {"x": 0.0, "y": 0.0, "z": 0.0},
      "orientation": {"x": 0.0, "y": 0.0, "z": 0.0, "w": 1.0},
      "linear_velocity": {"x": 0.1, "y": 0.0, "z": 0.0},
      "angular_velocity": {"x": 0.0, "y": 0.0, "z": 0.0}
    }
  ],
  "lidar_scans": [
    {
      "frame_id": "laser",
      "timestamp": 1234567890,
      "angle_min": -3.14,
      "angle_max": 3.14,
      "range_min": 0.1,
      "range_max": 10.0,
      "ranges": [1.0, 1.1, 1.2, ...]
    }
  ],
  "images": ["path/to/image.jpg"],
  "imu_readings": []
}
```

### 2. Агрегация батчей (`Formater`)

Система накапливает последние `N` батчей (по умолчанию 3) для анализа более длинных последовательностей движения. Это позволяет обнаруживать паттерны, которые не видны в одном батче.

**Класс**: `ml.model.model_input_formater.Formater`

- `add(data)`: Добавляет новый батч в буфер
- `get()`: Возвращает объединенные данные из последних N батчей
- `flush()`: Очищает буфер после обработки

### 3. Проверка достаточности данных

Если количество записей одометрии < 95, система возвращает "тихий" ответ:
```json
{
  "interest": 0,
  "joke": ""
}
```

### 4. Предобработка данных (`preprocess.py`)

#### 4.1. Обработка изображений
- Использует модель **BLIP** (Salesforce/blip-image-captioning-large)
- Генерирует текстовое описание последнего изображения с камеры
- Формат: `"Data from camera: [описание]."`

#### 4.2. Вычисление поведенческих индикаторов

Из одометрии вычисляются **16 метрик** (все нормализованы в диапазон [0, 1]):

1. **cleaned_avg_linear_speed** — Нормализованная средняя скорость (адаптивная нормализация по максимуму в траектории)
2. **speed_variance** — Стабильность скорости (инвертированная дисперсия)
3. **angular_zcr** — Zero Crossing Rate для угловой скорости (частота смены знака)
4. **mid_stop_ratio** — Отношение остановок в середине траектории
5. **zcr_angular_vel** — ZCR для продольной скорости
6. **progress_consistency** — Консистентность прогресса (отношение прямого расстояния к пройденному пути)
7. **angular_smoothness** — Плавность угловых движений
8. **area_redundancy** — Избыточность площади (отношение среднего расстояния до центра к общему пути)
9. **oscillation_ratio** — Коэффициент осцилляций (движения туда-сюда)
10. **acceleration_stability** — Стабильность ускорения
11. **velocity_direction_coherence** — Согласованность направления скорости и движения
12. **trajectory_entropy** — Энтропия траектории (разнообразие посещенных ячеек)
13. **hurst_exponent** — Экспонента Херста (тренд vs случайное блуждание)
14. **jarque_bera_acceleration** — Тест Жарка-Бера на нормальность ускорения
15. **path_curvature** — Кривизна пути
16. **speed_coefficient_of_variation** — Коэффициент вариации скорости

**Математические формулы** описаны в `formulas.md`.

#### 4.3. Классификация аномалий

- Загружается обученный классификатор из `ml/utils/classifier.pkl`
- На вход подается DataFrame с 16 индикаторами
- Классификатор возвращает вероятность аномалии (0-1)
- **Порог**: 0.6 — если вероятность < 0.6, возвращается пустой ответ

### 5. Генерация ответа через LLM

Если аномалия обнаружена, данные передаются в языковую модель:

- **Модель**: Ollama с Qwen3-4B-GGUF (конфигурируется в `model_config.json`)
- **Температура**: 0.5 (баланс между креативностью и стабильностью)
- **System Prompt**: "Ты - внутренняя система робота, созданная для описания его ошибок работы с помощью смешных шуток..."
- **Query**: `"{model_input}. Пошути креативно на тему ошибки в работе системы робота."`

Модель генерирует ответ, который парсится (удаляется часть до `</think>`).

### 6. Формирование ответа

```json
{
  "interest": 1,
  "joke": "Робот решил, что он балерина и начал кружиться на месте..."
}
```

## 🧠 Модели машинного обучения

### 1. TCN (Temporal Convolutional Network)

**Файл**: `ml/tcn/tcn.py`

Архитектура для классификации временных последовательностей:
- **Вход**: (Batch, Time_Steps, Features) — последовательность одометрии + лидара
- **TCN блок**: Causal свертки с расширенными рецептивными полями
- **Классификатор**: Полносвязные слои для финальной классификации
- **Выход**: Логиты для классов поведения

**Использование**: Обучение на исторических данных робота (см. `predictor_learning.ipynb`)

### 2. BLIP Image Captioning

**Файл**: `ml/image_model/image_model.py`

- **Модель**: `Salesforce/blip-image-captioning-large`
- **Назначение**: Генерация текстовых описаний изображений с камеры робота
- **Интеграция**: LangChain Runnable для использования в цепочках

### 3. Классификатор аномалий

**Файл**: `ml/utils/classifier.pkl`

Обученная модель (вероятно, scikit-learn) для бинарной классификации:
- **Вход**: 16 поведенческих индикаторов
- **Выход**: Вероятность аномалии [0, 1]
- **Порог**: 0.6

### 4. LLM (Ollama/Qwen3)

**Конфигурация**: `ml/model_config.json`

```json
{
  "model-name": "hf.co/unsloth/Qwen3-4B-GGUF:IQ4_XS",
  "temperature": 0.5,
  "system-prompt": "...",
  "basic-query": "{model_input}. Пошути креативно..."
}
```

**Загрузка**: Автоматически через `ml/utils/load_models.py` при старте

## 🔬 Детальное описание компонентов

### Backend (`backend/`)

#### `main.py`
- FastAPI приложение
- Эндпоинт `/generate` для приема телеметрии
- Валидация через Pydantic модели
- Обработка ошибок и возврат ответов

#### Модели данных (`backend/models/`)

- **`RobotInput`**: Входные данные с робота
  - `batch_id`, временные метки
  - `odometries`: список одометрии
  - `lidar_scans`: список сканов лидара
  - `images`: пути к изображениям
  - `imu_readings`: данные IMU (опционально)

- **`RobotResponse`**: Ответ системы
  - `interest`: 0 или 1 (интересность события)
  - `joke`: текстовое описание/шутка

- **`OdometryData`**: Структура одометрии
  - Позиция (Vector3)
  - Ориентация (Quaternion)
  - Линейная и угловая скорости (Vector3)

- **`LidarScan`**: Структура скана лидара
  - Углы и диапазоны
  - Массив расстояний

### ML модули (`ml/`)

#### `config.py`
- Инициализация конфигурации из `model_config.json`
- Создание форматтера батчей
- Загрузка моделей через `load_models.py`

#### `model/model_interface.py`
- **`get_model_reply(robot_info)`**: Главная функция обработки
  - Агрегация батчей
  - Проверка достаточности данных
  - Вызов предобработки
  - Генерация ответа через LLM
  - Возврат результата

#### `utils/preprocess.py`
- **`preprocess_data(output)`**: Главная функция предобработки
  - Обработка изображений через BLIP
  - Вычисление 16 поведенческих индикаторов
  - Классификация аномалий
  - Формирование строки для LLM

- **`compute_behavioral_indicators(data_dict)`**: Вычисление метрик
  - Извлечение позиций и временных меток
  - Сглаживание траектории (Savitzky-Golay фильтр)
  - Вычисление скоростей и ускорений
  - Расчет всех 16 индикаторов

- **`preprocess_image(camera_output)`**: Обработка изображений
  - Загрузка BLIP модели (ленивая)
  - Генерация подписи к последнему изображению

#### `tcn/tcn.py`
- **`RobotTCNClassifier`**: PyTorch модель
  - TCN блок для временных последовательностей
  - Классификатор на выходе
  - Causal свертки (не заглядывает в будущее)

#### `tcn/predictor.py`
- **`Predictor`**: Класс для обучения и предсказания
  - Метод `fit()`: обучение с валидацией
  - Метод `predict()`: предсказание на новых данных
  - Интеграция с TensorBoard для логирования
  - Метрики: Loss, F1-score

#### `image_model/image_model.py`
- **`BLIPImageCaptioner`**: LangChain Runnable
  - Ленивая загрузка модели BLIP
  - Поддержка путей к файлам и PIL.Image
  - Генерация подписей с настраиваемой длиной

#### `model/model_input_formater.py`
- **`Formater`**: Агрегация батчей
  - Хранение последних N батчей
  - Рекурсивное объединение словарей и списков
  - Очистка буфера после обработки

## 📊 Формулы поведенческих индикаторов

Подробные математические формулы описаны в `formulas.md`. Основные метрики:

- **cleaned_avg_linear_speed**: `min(1, max(0, v_avg / max(0.1, v_max)))`
- **speed_variance**: `min(1, max(0, 1 - σ_v / (0.8·v_avg + 0.1)))`
- **angular_zcr**: `min(1, max(0, 1 - (1/0.3) · (N_zc / N)))`
- **progress_consistency**: `min(1, max(0, ||p_N - p_1|| / Σ||p_{i+1} - p_i||))`
- И другие...

## 🛠️ Разработка и обучение моделей

### Обучение TCN классификатора

1. Подготовьте данные в формате `.npz`:
   - `robot_data_train.npz`: обучающая выборка
   - `robot_data_test.npz`: тестовая выборка

2. Используйте ноутбук `ml/tcn/predictor_learning.ipynb`:
   ```python
   from ml.tcn.predictor import Predictor
   
   predictor = Predictor(
       input_dim=16,  # Количество признаков
       num_classes=2,  # Нормальное/аномальное
       tcn_channels=[32, 64, 64],
       epochs=20
   )
   
   predictor.fit(X_train, y_train, eval_set=(X_val, y_val))
   predictor.save('model.pth')
   ```

### Обучение классификатора аномалий

Используйте scikit-learn для обучения классификатора на 16 индикаторах:

```python

# Загрузите данные с индикаторами и метками
X, y = load_data()

# Обучите модель

# Сохраните
```

## 📝 Заметки и ограничения

1. **Минимальное количество данных**: Система требует минимум 95 записей одометрии для анализа
2. **Агрегация батчей**: По умолчанию анализируются последние 3 батча
3. **Порог аномалий**: 0.6 — настраивается в `preprocess.py`
4. **Векторная БД**: Qdrant интерфейс закомментирован, но может быть активирован для хранения истории
5. **GPU**: BLIP и TCN автоматически используют CUDA, если доступно
